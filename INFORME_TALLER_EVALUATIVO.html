2. Introducción y Elección Tecnológica

Para este taller evaluativo se solicitó construir una aplicación básica para gestionar un catálogo de productos. Como estudiante de desarrollo de software, decidí utilizar Python debido a su sintaxis clara, legible y directa.

Para almacenar los datos, se eligió una combinación de estructura en memoria mediante diccionarios y guardado en un archivo productos.json. De esta forma el sistema es rápido, no requiere configurar bases de datos externas complicadas, y al mismo tiempo evita que la información se pierda cuando se cierra el programa.

Objetivo del proyecto: Demostrar el funcionamiento de las operaciones CRUD (Crear, Leer, Actualizar, Eliminar), asegurar su correcto funcionamiento mediante pruebas unitarias automáticas y validar que el código esté bien estructurado para su posterior análisis con SonarQube y publicación en GitHub.

3. Estructura de Archivos del Proyecto

Para que el código no fuera un solo archivo desordenado, se separaron las responsabilidades en módulos sencillos y fáciles de entender:

  • product_manager.py: Es el archivo principal donde está programada la lógica del CRUD. Define la clase ProductManager con todas las funciones para manipular productos y validar los datos.
  • test_product_manager.py: Archivo dedicado exclusivamente a las pruebas unitarias usando la librería oficial unittest de Python.
  • main.py: Es el menú que aparece en la terminal con opciones del 1 al 6 para que cualquier persona pueda probar el sistema escribiendo por teclado.
  • productos.json: Archivo de texto plano donde se van guardando los productos automáticamente.
  • sonar-project.properties: Archivo con la configuración necesaria para que SonarQube entienda qué archivos analizar.
  • README.md: Guía de usuario con instrucciones paso a paso.

4. Implementación del CRUD de Productos

Siguiendo los requerimientos de la guía, cada producto cuenta con los siguientes campos:

  • id: Identificador único que no se puede repetir (ej. "P001").
  • nombre: Nombre comercial del producto (no puede estar vacío).
  • descripcion: Breve explicación de sus características.
  • precio: Valor monetario numérico (no se permiten números negativos).
  • cantidad: Cantidad de unidades en bodega (entero mayor o igual a 0).

Explicación sencilla de las operaciones CRUD:

  1. Crear (crear_producto): Revisa primero que el ID no exista ya en el sistema y que los precios no sean negativos. Si todo está correcto, agrega el producto al diccionario y actualiza el archivo JSON. Si hay un error, avisa con un mensaje descriptivo.
  2. Leer (obtener_producto / listar_productos): Permite buscar un producto por su código para ver sus detalles, o traer la lista completa para mostrársela al usuario en forma de tabla.
  3. Actualizar (actualizar_producto): Busca el producto por su ID. Si existe, permite modificar el nombre, precio, stock o descripción sin borrar los datos que no se deseen cambiar.
  4. Eliminar (eliminar_producto): Busca el ID en el registro y lo borra de la lista y del archivo JSON de forma definitiva.

5. Pruebas Unitarias (Testing Automatizado)

Una prueba unitaria es un pequeño programa que ejecuta una función de nuestro código con datos de prueba para comprobar automáticamente si responde como se espera. La guía solicitaba al menos un caso exitoso y un caso de error para cada una de las 4 operaciones.

Operación Caso Exitoso (Happy Path) Caso de Error (Manejo de Excepciones)
Crear Se ingresan datos válidos y el producto queda registrado en el inventario. Se intenta ingresar un ID que ya existe, o se ingresa un precio/cantidad negativa. El sistema lanza ValueError.
Leer Se consulta un producto existente por su ID y devuelve sus datos correctos. Se consulta un ID inexistente. El sistema detecta el error y lanza KeyError.
Actualizar Se modifica el precio y nombre de un producto existente y se guardan los cambios. Se intenta actualizar un producto que no existe, o con precio negativo. El sistema rechaza la operación.
Eliminar Se elimina un producto y se comprueba que la lista disminuye y ya no existe. Se intenta eliminar un ID que no existe. El sistema lanza KeyError.

Ejecución y Verificación de los Resultados:

Las pruebas se ejecutan directamente desde la terminal con el comando nativo de Python:

python -m unittest test_product_manager.py -v

6. Prueba de Calidad de Código con SonarQube

SonarQube es una herramienta que revisa el código fuente en busca de errores ("bugs"), vulnerabilidades de seguridad y "code smells" (código desordenado o difícil de mantener).

Para realizar el análisis, se configuró el archivo sonar-project.properties en la raíz del proyecto: 

sonar.projectKey=crud-productos-python
sonar.projectName=CRUD Productos Python
sonar.projectVersion=1.0
sonar.sourceEncoding=UTF-8
sonar.sources=.
sonar.exclusions=test_*.py,venv/**,.git/**,__pycache__/**
sonar.tests=.
sonar.test.inclusions=test_*.py
sonar.language=py
Resumen de Calidad Obtenido:
  • Bugs: 0 (cero errores lógicos que puedan romper el programa).
  • Vulnerabilidades: 0 (cero fallos de seguridad detectados).
  • Code Smells: 0 (código limpio, funciones cortas y tipado claro).
