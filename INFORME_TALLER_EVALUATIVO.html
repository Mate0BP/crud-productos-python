Estructura del Proyecto y CRUD

3. Configuración Inicial y Archivos del Proyecto

Organicé el proyecto en archivos separados para que el código quede ordenado y fácil de revisar:

  • product_manager.py: Contiene la clase ProductManager. Aquí están las funciones que crean, buscan, editan y borran productos.
  • test_product_manager.py: Contiene las pruebas unitarias usando la librería estándar unittest de Python.
  • main.py: Es el menú principal que se ve en la pantalla de la consola para usar el programa interactivamente con números del 1 al 6.
  • productos.json: El archivo donde se van guardando los datos de forma automática.
  • sonar-project.properties: Archivo básico de configuración para el análisis de calidad con SonarQube.

4. Implementación del CRUD de Productos

Cada producto que se registra tiene los 5 datos que pide la guía:

  • id: Código único para que no haya dos productos iguales (ejemplo: "1" o "P01").
  • nombre: Nombre del producto (ejemplo: "Teclado").
  • descripcion: Breve detalle de lo que es el producto.
  • precio: Valor en dinero (no se aceptan números negativos).
  • cantidad: Número de unidades disponibles (no se aceptan números negativos).

¿Cómo funcionan las 4 operaciones en el código?

  1. Crear (crear_producto): Pide los datos. Si el ID ya existe o el precio es menor que cero, muestra un error y no lo guarda. Si todo está bien, lo añade a la lista y lo guarda en el archivo JSON.
  2. Leer (obtener_producto y listar_productos): Permite buscar un producto escribiendo su ID, o mostrar todos los productos registrados en una tabla.
  3. Actualizar (actualizar_producto): Busca el producto por su ID. Si existe, podemos cambiarle el nombre, precio, descripción o cantidad.
  4. Eliminar (eliminar_producto): Borra el producto del sistema y actualiza el archivo JSON.

5. Pruebas Unitarias para el CRUD

Las pruebas unitarias sirven para comprobar de manera automática que cada función haga exactamente lo que debe hacer, tanto cuando el usuario escribe datos correctos como cuando comete un error.

Para cumplir con la guía, creé pruebas con casos de éxito y casos de error:

Operación Prueba de Éxito Prueba de Error
1. Crear Crear un producto válido y comprobar que se guardó correctamente. Intentar guardar con un ID repetido o precio negativo. El sistema lo rechaza con un ValueError.
2. Leer Buscar un producto que sí existe y recibir sus datos. Buscar un producto con un ID que no existe. El sistema avisa el error con un KeyError.
3. Actualizar Modificar el precio y nombre de un producto y verificar el cambio. Intentar actualizar un ID inexistente o poner precio negativo.
4. Eliminar Borrar un producto y verificar que ya no aparece en la lista. Intentar borrar un ID que no existe en el sistema.

6. Prueba de Calidad con SonarQube

Para revisar la calidad del código utilicé SonarQube. Esta herramienta revisa que el código no tenga errores comunes, fallas de seguridad o partes mal escritas.

Configuré el archivo sonar-project.properties en la raíz del proyecto para indicarle que el lenguaje es Python: 

sonar.projectKey=crud-productos-python
sonar.projectName=CRUD Productos Python
sonar.projectVersion=1.0
sonar.sources=.
sonar.exclusions=test_*.py,venv/**,.git/**
sonar.tests=.
sonar.test.inclusions=test_*.py
sonar.language=py
